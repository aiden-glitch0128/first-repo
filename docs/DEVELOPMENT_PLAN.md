# 끝까지 v0.2 개발계획서 — AI 편집국
작성: 2026-10-16

## 제품 목표
저자가 소재 수집부터 갈무리, 기획, 초안, 퇴고, 완성까지 책 한 권을 끝낼 수 있도록 돕는 **프로젝트 중심 AI 편집국**. 성공 지표는 대화량이 아니라 단계 전환, 완성된 장, 최종 완성된 책이다.

## 원칙
- 총괄 편집장이 전체 맥락을 유지하고 전문 역할(인터뷰어·기획 편집자·원고 편집자·검토자)을 필요할 때 호출한다.
- AI는 제안하고 저자가 승인한다. AI의 판단만으로 원고·목차·단계를 변경하지 않는다.
- 소재 목표 개수는 사용자가 결정한다. 50%, 75%, 100% 도달 시 리뷰를 제안하되, 목표 미달이어도 갈무리할 수 있다.
- 다양성만 보지 않고 **주제 연결성·관점 다양성·집필 가능성·책 구성 가능성**을 근거와 함께 평가한다. 숫자 점수는 강제하지 않는다.
- 과도한 소재 수집과 퇴고를 경계하고, 모든 AI 상호작용을 다음 행동이나 편집 결정으로 연결한다.
- 현재 브라우저에 있는 v0.1 원고를 잃지 않는다. 백업/복원 제공.

## 집필 단계
1. 소재 수집: 사용자 목표 설정, 소재 입력, AI 인터뷰, 50/75/100% 리뷰
2. 소재 갈무리: 주제 군집화, 중복/공백 분석, 저자의 선택
3. 책 기획: 주제·독자·잠정 목차·완료 기준 합의 (장 수는 이때 설정)
4. 초안 집필: 장별 작은 미션과 막힘 해소
5. 원고 다듬기: 구조·논리·문장 검토, 저자 승인
6. 완성: 체크리스트, 내보내기, 프로젝트 종료

## v0.2 1차 구현 범위
- 기존 localStorage 키와 v0.1 자료를 그대로 사용하며 새 필드만 추가
- 소재 목표 설정과 마일스톤 도달 감지(중복 리뷰 방지)
- 총괄 편집장 API: 서버 환경변수 OPENAI_API_KEY를 사용해 프로젝트 맥락·소재를 검토
- AI 리뷰 결과는 구조화하여 브라우저 프로젝트 상태에 저장; AI 제안은 자동 적용하지 않음
- 리뷰 시점이 아니어도 수동 AI 리뷰 가능
- JSON 백업 및 JSON 복원(복원 전 확인)
- AI 미설정 시 기존 집필 기능 정상 동작, 명확한 오류 안내

## 데이터 모델
- 기존: projectTitle, dailyChars, streak, lastCompletedDate, items
- 신규: materialGoal(기본 40), editorialReviews[{id,createdAt,milestone,summary,connections,diversity,gaps,readiness,nextAction,questions}], reviewedMilestones(기록)
- 향후: projectIntent, authorVoice, editorialDecisions, chapters, stage, bookCompletionCriteria, manuscriptVersions
- 소재 집계는 과거 단계로 이동한 소재도 포함해 원본(material)과 파생(selected/draft/manuscript)을 중복 계산하지 않는다. v0.2에서는 원본 id/parentId 계보 기준.

## AI 호출 정책
- 브라우저에서 API 키를 취급하지 않는다. Next.js 서버 라우트에서 OpenAI API 호출.
- 프로젝트 제목과 소재 제목/본문이 외부 AI API로 전송될 수 있음을 사용자에게 표시.
- 입력 크기 및 출력 토큰 제한, 서버 측 오류 처리, 임의 변경 금지.
- 공개 배포에서 인증 없는 AI API는 남용/비용 위험이 있다. 첫 버전은 서버 비밀 설정 및 요청 제한을 고려하고, 실제 공개 운영 전에 인증·서버 측 rate limit·비용 한도를 필수 도입한다.
- 프로젝트 기억은 명시적 구조화 데이터로 관리. 대화 기록에만 의존하지 않는다.

## 단계별 출시 기준
- P1(이번 PR): 목표/마일스톤, 리뷰 저장, AI 편집장 리뷰, 백업 복원, 기존 데이터 호환
- P2: 인터뷰 질문과 답변의 소재 반영, 편집 결정 로그, 갈무리 워크플로
- P3: 목차/장 구조, 집필 미션과 진행 측정
- P4: 전문 에이전트 선택적 협업, 퇴고 승인·버전 관리
- P5: 최종 원고 내보내기, 클라우드 동기화 및 다기기 충돌 해결

## 검증 체크리스트
- 기존 v0.1 로컬 데이터가 로드되고 변경 없이 보존되는가
- 소재 목표 변경/50·75·100% 도달 표시가 정확한가
- 리뷰 호출 실패 시 원고와 상태가 안전한가
- AI 리뷰가 사용자 동의 없이 소재나 원고를 수정하지 않는가
- JSON 복원 실패 시 기존 데이터가 유지되는가
- 모바일 화면에서 입력과 리뷰가 가능한가
- OPENAI_API_KEY가 브라우저 번들/응답에 노출되지 않는가

## 배포
GitHub 기능 브랜치 → PR 검토 → main 병합 → Vercel 자동 배포. OPENAI_API_KEY는 Vercel 서버 환경변수에 설정. API 키 미설정 상태에서도 기존 기능은 사용 가능.
