# 끝까지

**책 한 권을 끝내기 위한 집필 시스템**

출판 여부보다 "끝까지 완성했다"는 경험을 만드는 데 초점을 둔 개인 집필 앱입니다.

## MVP 원칙

- 매일 사용자가 고민하지 않도록 **오늘 할 일 하나**를 제시한다.
- 글자 수보다 **소재 → 채택 → 초안 → 원고**의 이동을 진행률로 본다.
- 소재만 모으며 회피하지 않도록 일정량 이후에는 채택/초안 작업을 우선한다.
- 연속 집필 일수를 기록한다.
- 모든 데이터는 우선 브라우저 localStorage에 저장하고 JSON 백업을 제공한다.

## 실행

```bash
npm install
npm run dev
```

브라우저에서 `http://localhost:3000` 접속.

- JSON 백업 및 복원, 기존 v0.1 로컬 데이터 호환

### AI 연결

Vercel 프로젝트의 **Settings → Environment Variables**에서 서버 환경변수 `OPENAI_API_KEY`와 **20자 이상 임의의 비밀 문자열** `EDITOR_ACCESS_TOKEN`을 등록하고 재배포하세요. 앱의 비밀번호 입력창에 동일한 `EDITOR_ACCESS_TOKEN`을 입력해야 AI 기능을 사용할 수 있습니다. 이 값은 `NEXT_PUBLIC_`으로 시작하면 안 됩니다. 선택적으로 `OPENAI_MODEL`을 설정할 수 있으며 기본값은 `gpt-4o-mini`입니다. **`NEXT_PUBLIC_` 접두사를 API 키에 붙이지 마세요.** 키가 없으면 AI 검토만 사용할 수 없고 기존 집필 기능은 동작합니다.

**주의:** AI 검토 요청 시 소재 제목·본문과 프로젝트 제목이 외부 OpenAI API로 전송됩니다. 저장된 데이터는 기본적으로 해당 브라우저에만 있습니다. 현재 AI 엔드포인트에는 사용자 인증 및 서버 측 사용량 제한이 없어, 공개 서비스에 API 키를 설정하면 제3자의 호출로 비용이 발생할 수 있습니다. **실서비스 공개 전에 인증·사용량 제한·비용 한도를 반드시 추가하세요.** 개인 테스트라도 API 키 사용량 한도를 설정하고, 사용하지 않을 때는 키를 제거하는 것을 권장합니다.

전체 로드맵과 테스트 항목은 [개발계획서](docs/DEVELOPMENT_PLAN.md)를 참고하세요.

### 인터뷰어 및 편집 결정 기록
- AI 인터뷰어는 기존 소재 제목, 최근 인터뷰 문답, 편집 결정을 참조하여 한 번에 한 질문을 합니다.
- 답변은 원고에 자동 반영되지 않습니다. 사용자가 **내 답변을 소재로 저장**을 눌러야 소재가 됩니다.
- 리뷰 후 **이번 회의의 내 결정 기록하기**를 통해 저자 결정을 별도 저장합니다.
- 접근 코드는 현재 탭의 sessionStorage에 저장되며, 원고 및 편집 기록은 기존 localStorage에 저장됩니다.
- 인증 전환 이전의 임시 보호: 서버 측 코드 검사 + 인스턴스별 시간당 12회 제한. **서버리스 인스턴스마다 제한이 따로 적용되고 재시작하면 초기화되므로 전역적인 남용 방지는 아닙니다.** 공개 운영 전 서버 측 지속형 rate limiting, 사용자 인증, 비용 제한을 추가해야 합니다.
